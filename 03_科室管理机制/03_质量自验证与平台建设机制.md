# 质量自验证与平台建设机制

## 1. 机制定位

本文用于把自验证、评审、CBB 和平台化建设从“重要不紧急”变为可检查、可验收的科室机制。

## 2. 自验证准入准出

| 阶段 | 要求 |
| --- | --- |
| 准入 | 需求边界明确，方案或修改点有记录，测试范围已确认 |
| 执行 | 有用例、有结果、有问题记录、有责任人 |
| 准出 | 关键用例通过，遗留问题有风险评估，报告可追溯 |

## 3. 自验证报告最小字段

| 字段 | 说明 |
| --- | --- |
| 项目/版本 | 对应项目和软件版本 |
| 验证范围 | 本次验证覆盖和不覆盖内容 |
| 用例结果 | 通过、失败、阻塞 |
| 遗留问题 | 问题描述、影响、责任人、计划关闭时间 |
| 风险评估 | 是否影响集成、挂飞、测评或交付 |
| 准出结论 | 是否允许进入下一阶段 |

## 4. 评审机制

| 评审对象 | 评审重点 | 参与人 |
| --- | --- | --- |
| 重点项目方案 | 需求边界、技术路径、风险和验证方法 | 主任设计师、模块 Owner、SE/XQA |
| 平台化方案 | 共性接口、复用范围、迁移风险 | 田超华、刘平、陈杰、梁加明 |
| B 角输出 | 任务理解、代码质量、自验证结果 | 对应 A 角，你抽查 |

## 5. 年度平台化建设绑定

| 工作 | 主责 | 质量要求 |
| --- | --- | --- |
| 链路层数据面通用化 V2.0 | 你 | 每个模块有接口说明、配置测试用例和自验证报告 |
| 一体化协议平台 | 田超华 | 组件独立管理、OS 抽象层清晰、关键性能有基线 |
| 网络层 V2.0 | 陈杰、梁加明 | 模块化规范、接口说明、自验证报告齐套 |
| CBB 规范建设 | 各模块 Owner | 从真实模块中提炼，不单独空转 |

## 6. 月度检查

| 检查项 | 标准 |
| --- | --- |
| 自验证执行率 | 重点项目网络协议自验证执行率不低于 90% |
| 评审覆盖率 | 新功能和平台化方案/代码评审覆盖率不低于 80% |
| 问题闭环 | 严重问题 100% 输出分析报告和改进措施 |
| 平台化进度 | 每月能看到明确输出物，不以“项目太忙”作为长期延期理由 |
