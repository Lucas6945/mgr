# 任务与过程管理机制

## 1. 机制定位

本文用于把科室管理从“负责人随时兜底”调整为“任务清楚、节点可查、风险及时升级”。适用于周会、站会、重点项目检查、年度非交付重点工作推进。

## 2. 基本原则

1. 每项任务必须有责任人、截止时间、输出物和验收方式。
2. 重点任务用 99%/50%/1% 三段检查，不等最后一天暴露风险。
3. 风险按影响范围分层，超过责任人能力边界时必须升级。
4. 项目交付任务和年度建设任务同等进入看板，避免平台化建设长期被挤压。

## 3. 周节奏

| 节点 | 动作 | 输出 |
| --- | --- | --- |
| 周一 | 确认本周重点任务和关键风险 | 周任务看板 |
| 周中 | 检查 P0/P1 任务 50% 状态 | 问题清单、支援动作 |
| 周五 | 复盘完成情况和下周风险 | 周报、风险台账 |
| 月底 | 检查年度非交付重点工作 | 月度里程碑记录 |

## 4. 任务看板字段

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 一句话说明任务 |
| 来源 | 项目交付、年度建设、人员培养、临时插入 |
| 优先级 | P0/P1/P2/P3 |
| 责任人 | 最终负责推进的人 |
| 协作人 | 参与执行或评审的人 |
| 截止时间 | 明确到日期 |
| 输出物 | 文档、代码、验证报告、问题闭环等 |
| 检查节点 | 99%、50%、1% 分别查什么 |
| 当前风险 | 影响、原因、需要支持 |
| 下一步动作 | 下一次可检查动作 |

## 5. 风险分层

| 等级 | 定义 | 处理方式 |
| --- | --- | --- |
| P0 | 当天不处理会导致项目停摆、版本阻塞或外场重大问题 | 当天响应，你或主责骨干压阵，必要时向上同步 |
| P1 | 影响重点项目节点或关键验证 | 1-2 天内给处理路径，周中检查 |
| P2 | 常规维护、小功能、明确边界问题 | 按周计划推进，要求记录和自验证 |
| P3 | 可延期优化、新特性、非当前版本必须项 | 排期或延期，必要时和项目经理确认 |

## 6. 检查方式

| 检查点 | 要查的问题 |
| --- | --- |
| 99% | 任务是否真正理解，输出物和验收标准是否明确 |
| 50% | 方向是否偏差，是否有阻塞，是否需要支援 |
| 1% | 是否完成自验证、评审记录、问题闭环和风险说明 |
