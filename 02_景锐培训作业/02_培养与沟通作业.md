# 培养与沟通作业

> 来源：景锐培训中的差异化领导、员工培养、反馈沟通和技术冲突处理作业，结合链路层科室人员现状整理。

| 人员 | 当前特点 | 建议领导方式 | 具体动作 |

## 3. 1对1沟通提纲

### 3.1 湘湘

目的：把湘湘从执行骨干推到定向组网方向负责人。

沟通要点：

1. 先认可：你已经能承担定向组网方向的核心判断，不只是执行任务。
2. 再授权：后续 TDMA 组网、无中心、分裂融合、分层分簇等方向，日常问题先由你牵头。
3. 给边界：关键节点、跨科室争议和高风险方案我来压阵，不让你单独背全部风险。
4. 给带教要求：汪泰利是你的 B 角，任务要拆小，输出要有验收。

### 3.2 任霜

目的：推动资源管理交接，同时让任霜感到被尊重。

沟通要点：

1. 先认可：资源管理方向这块你最熟，很多经验只有你能讲清楚。
2. 明确目的：交接不是给你加活，而是让你休假后不用被反复追问，也让你的经验成为团队资产。
3. 降低压力：不要求一次写完整手册，每周留下一个能用的小包就行。
4. 给支持：符兵负责记录、验证和台账整理；周非凡仅在共性学习范围内旁听或辅助验证，不作为资源管理主承接人。

### 3.3 汪泰利

目的：帮助其建立胜任感和稳定输出节奏。

沟通要点：

1. 任务不会一上来给大而复杂的方案，而是从明确小模块开始。
2. 每个任务必须先写清目标、输入、输出、风险和疑问。
3. 做到 50% 时主动同步，不等最后交付才反馈。
4. 完成一个闭环后会在组内明确认可。

### 3.4 符兵

目的：让符兵成为资源管理方向中低风险事项承接人。

沟通要点：

1. 你不是替代任霜，而是先接住常规事项和中低风险任务。
2. 学习资源管理时要能复述主流程、跑通验证、记录问题。
3. 遇到复杂问题时，先按“现象、版本、复现、初判、需要支持”整理，再升级。
4. 第一次独立闭环会作为成长里程碑。

### 3.5 周非凡

目的：完成入职启动并明确全向主方向。

沟通要点：

1. 主方向先定为全向链路层，先把全向 TDMA/SPMA、问题复盘和自验证基本功打牢。
2. 前期任务以环境、文档、小需求、问题复盘和 1315 需求分析为主。
3. 定向资源管理只作为共性学习，不要求你短期接复杂问题。
4. 每周输出一页学习记录，便于跟踪成长。

## 4. 技术冲突处理作业

场景：组员 A 和 B 在某项目技术方案中发生严重分歧，争执两天，影响项目进度。

处理步骤：

1. 分别听取 A 和 B 的方案，要求各自说明核心思路、优势、风险、代价和依赖条件。
2. 对照当前项目核心约束，按进度、可靠性、可维护性、可验证性四个维度评估。
3. 做出决策，可选择 A、B 或融合方案 C。
4. 开短会宣布结论，说明决策依据、分工、责任人和截止时间。
5. 设置复盘节点，方案执行到里程碑后复查未采纳方案中是否有可吸收价值。

安抚未采纳一方的话术：

> 今天没有采用你的完整方案，不代表你的判断没有价值。你提出的风险点我认可，也会放进当前方案的评审清单里。现在项目进度压力比较大，所以我先选择代价更小、验证路径更短的方案。接下来希望你作为风险评审人继续把关，后续如果条件成熟，我们可以把你的方案沉淀到下一轮架构优化里。

## 5. 任务分派作业

场景：主任临时插入 3 天数据核对工具任务，不增加人手，不影响核心模块。

分派建议：

| 角色 | 分派 |
| --- | --- |
| 主责 | 任务空间最大的低级别工程师，适合练手 |
| 质量把关 | 已完成主要开发但质量需提升的成员做 Review |
| 你 | 只负责需求确认、关键节点把关和最终验收，不亲自编码 |

过程控制：

1. 第 1 天确认需求理解和方案。
2. 第 2 天完成代码开发并进行 Review。
3. 第 3 天完成测试验证和交付。
4. 每天 10 分钟同步进度和卡点。
5. 提前和主任确认验收标准，避免最后一天返工。
