# 培养与沟通作业：任霜资源管理专项

> 说明：以下内容可将“任霜”替换为“成员R”后脱敏提交。
> 归类：景锐培训作业原文/专项作业。涉及任霜培养沟通的长期执行材料，应同步参考 [资源方向产假前交接包.md](../04_人员梯队与沟通/资源方向产假前交接包.md)。

## 第一周：培养设计与第一次带教动作

### 作业1：识别成员的真实差距

**当前职责：**  
任霜目前负责链路层资源管理模块，是当前链路层中挑战较大、也最有潜力形成产品亮点的模块负责人。

**期望结果：**  
希望她能主动探索资源管理相关的需求场景和瓶颈点，主动挖掘特性深度；对评审后的问题能及时输出评估结论、阶段进展、风险和下一步计划；能沉淀清晰可见的KB页面，并主动推动测试资源协调和验证闭环。

**当前实际表现：**  
需求评审后连续一周没有输出评估结论和进展，自己分析后直接进入代码实现构思。每次沟通需求时，经常反馈“你把需求说清楚，你要什么东西”。平时很少主动同步进展，KB页面输出后也大多没有显性展示。需要测试结果时，多次反馈“没有设备，你要帮我协调设备”，没有主动提出替代验证方案、资源申请路径或风险升级。

**我观察到的事实：**

1. 资源管理需求评审结束后一周内，未主动输出评估结论、方案拆解、风险点或下一步计划，需要我追问后才同步。
2. 在测试结果推进中，多次以“没有设备”为主要阻塞点，但没有同步列出所需设备、验证用例、替代方案、协调对象和期望完成时间。

**初步差距判断及依据：**  
主要差距是状态意愿，其次是任务场景适配。她具备一定分析和实现能力，但对模块负责人角色的主动性、结果意识、过程透明度和向上管理意识不足。需求确实存在不明确点，但她更多停留在等待需求被完全说清楚，而不是主动澄清、拆解假设、输出阶段性判断并推动资源闭环。

### 作业2：设计一次721培养动作

**10%：知识或资料**  
提供资源管理模块的目标定位、产品亮点判断标准、历史问题清单、竞品或优秀方案参考、需求澄清模板、评估结论模板、测试资源申请流程和优秀KB样例。重点让她知道：模块负责人不仅是写代码，还要主动识别场景、输出判断、推动验证和形成可复用沉淀。

**20%：指导、示范、反馈**  
安排一次1:1沟通，先对齐我对资源管理模块负责人的期待：每周至少一次主动同步，评审后48小时内输出初步评估，阻塞问题要带着选项和建议来沟通。

我示范一次如何把“不明确需求”拆成：已明确部分、待确认问题、我的假设、方案选项、风险、验证计划。然后让她用当前资源管理需求现场练习一次，我当场反馈她的问题是否具体、结论是否清楚、下一步是否可执行。

同时调整我的沟通方式，先听她对需求不明确点的判断，再要求她给出自己的建议，避免只用催促方式推动。

**70%：真实任务练习**  
安排她在当前资源管理模块中完成一次真实闭环任务：

1. 在2天内输出《资源管理需求评估结论》，包含需求场景、用户价值、当前瓶颈、方案选项、风险点、测试资源需求和下一步计划。
2. 在1周内完成至少1个关键场景的验证设计，明确需要的设备、测试步骤、预期结果、无法验证时的替代方案。
3. 每周固定主动同步一次进展，内容包括已完成、当前阻塞、需要协助、下周计划。
4. 将阶段性结论沉淀到KB，并在团队内显性分享一次。

**我准备提供的支持：**  
我会帮她明确模块目标和阶段验收标准，协助她第一次梳理需求澄清清单和测试资源协调路径；对她的评估文档给一次具体反馈；必要时帮她协调设备，但要求她先输出设备清单、验证目的和优先级。

**说明她完成成长的结果：**  
如果她能在评审后48小时内主动输出初步评估，一周内形成可讨论的方案和验证计划，遇到设备阻塞时主动提出资源清单和替代方案，并持续在KB中公开沉淀结论，就说明她从“等待需求明确和等待资源”开始转向“主动澄清、主动推进、主动输出”。

### 作业3：设计第一次OJT带教现场

**场景一：让她做做看**

**任务：**  
让任霜基于当前链路层资源管理需求，现场拆解一次需求评估结论。

**我具体怎么做：**  
我先给她一个模板，要求她当场写出“已明确需求、未明确问题、我的假设、方案方向、风险点、测试资源需求、下一步计划”。我不直接替她写答案，只在她卡住时追问：“你现在最不确定的是什么？”“如果设备不到位，你还有什么验证路径？”“你建议我先拍板哪一个问题？”

**希望她学会什么：**  
学会面对不明确需求时，不是等待别人说清楚，而是主动拆解问题、提出假设和建议。

**什么表现说明可以进入下一阶段：**  
她能独立输出一页评估结论，并且问题清单具体、方案有取舍、资源需求可协调、下一步有明确时间点。

**场景二：反馈改善**

**任务：**  
针对她一周未主动输出进展、测试资源阻塞未闭环的问题做一次反馈。

**我具体怎么做：**  
先描述事实：“评审后一周内我没有看到评估结论；测试结果推进时，你多次反馈没有设备，但没有同步设备清单、验证目的和替代方案。”再说明影响：“这会让我无法判断模块风险，也会影响团队对资源管理模块亮点的判断。”然后邀请她表达困难，最后共同约定改进动作：以后评审后48小时内输出初评，阻塞超过1天必须同步阻塞原因、建议方案和需要谁协助。

**希望她学会什么：**  
学会主动汇报进展和风险，遇到阻塞时带方案沟通，而不是只反馈问题。

**什么表现说明可以进入下一阶段：**  
后续她能主动按约定同步进展，遇到设备问题时先给出清单、优先级、影响范围和替代验证方案，再请求协助。

## 第二周：真实沟通与复盘调整

### 作业4：围绕同一成员完成一次关键沟通

**沟通背景和目标：**  
32节点资源评估会议后，评审提出了多个问题，包括控制时隙降档等。会后我也单独和任霜沟通过跨团队交互方式：不等网络层、服务层先给结果，而是先按网络层、服务层开销为0进行评估，把剩余资源作为网络层、服务层后续优化必须达到的要求。但一周多过去后，她迟迟没有输出评审问题结论和下一步事项。此次沟通目标是了解真实原因，推动她及时汇报阶段结果，并形成后续沟通和输出机制。

**我观察到的事实：**  
32节点资源评审后，评审问题和下一步事项没有及时公开输出；我之前已经沟通过评估思路，但一周多没有看到正式结论、资源分配图或风险同步；其他模块需要基于她的资源评估结果安排后续优化，但目前缺少明确输入。

**我如何开场：**  
我先直接围绕事实询问：“当前32节点资源评估结果怎么样了？为什么连续一周多没有输出结果？”随后说明我关注的不是追责，而是项目节奏和技术风险：“这个模块是重点模块，你的判断很关键，但如果阶段结果一直不汇报，我无法判断整体方向是否正确，也无法协调其他模块提前进入工作。”

**我问了哪些问题：**

1. 目前32节点资源评估已经做到什么程度？
2. 评审会上提出的问题，哪些已经有结论，哪些还没有结论？
3. 你为什么选择先自己构思代码，而不是先输出阶段评估结果？
4. 你和网络层私下对接了什么内容？是否已经形成明确约束或资源要求？
5. 当前最影响你输出的困难是什么，是需求不清、方案不确定，还是担心结果不成熟？
6. 你需要我提供什么支持，才能先把阶段性结论输出出来？

**对方表达的真实困难、想法或需求：**  
她反馈评估结果已经有了，也私下和网络层做过对接。因为这个模块是内部重点模块，她希望自己先想清楚代码实现和资源分配逻辑，再和其他模块沟通具体安排和要求。她目前想先输出一版基础资源分配图，再进一步推动其他模块配合。她的真实想法是希望输出更成熟的结果，避免过早暴露不完整方案。

**双方形成的行动约定：**

1. 后续不等方案完全成熟，必须及时同步阶段性结果。
2. 对评审问题先输出当前判断、未闭环问题、风险点和下一步事项。
3. 32节点资源评估先形成一版基础资源分配图，并明确网络层、服务层需要达到的资源优化目标。
4. 后续涉及其他团队的事项，不只是私下沟通，要形成可见的结论和待办，便于项目整体把控。
5. 如果存在不确定点，需要明确列出假设条件、待确认问题和需要谁支持，而不是先长期独自推进。

**我提供的支持或准备争取的支持：**  
我会帮助她确认阶段性输出的标准，接受先输出“不完整但可讨论”的评估结论；必要时帮她协调网络层、服务层负责人参与资源约束确认；如果后续需要设备、测试资源或跨团队排期支持，我会向上级争取协调，但前提是她先给出明确的资源需求、影响范围和期望时间点。

### 作业5：实践复盘与下一步调整

**原来的判断哪些是对的：**  
我原来判断她存在主动汇报不足、过程不透明的问题是对的。她并不是没有进展，而是把结果放在自己手里，想等想清楚、做成熟后再同步。这会导致上层无法及时把控项目进度，也会让其他模块不能提前安排工作。

**哪些判断需要修正：**  
原来我更多判断她是状态意愿问题，但这次沟通后需要修正为：她不完全是不想做，而是对“阶段性输出”的理解不足，倾向于等结果成熟后再汇报。她有责任感，也重视模块质量，但缺少项目协同意识和风险前置同步意识。

**对方反应和预期有什么不同：**  
我原本预期她可能只是没有推进，实际她已经有评估结果，也私下和网络层做了对接。她的反应说明她不是完全被动，而是推进方式偏封闭，担心不成熟结果过早沟通。这个和我预期的“没有进展”不同。

**下一步准备继续做什么：**  
我会继续要求她围绕32节点资源评估输出阶段性成果，包括评审问题闭环表、基础资源分配图、网络层和服务层资源优化目标、当前风险和下一步计划。同时固定沟通节奏，要求她每周主动同步一次关键进展，遇到阻塞超过一天要及时暴露问题和需要的支持。

**需要向上级、同级或团队争取什么支持：**  
需要向上级争取对32节点资源评估的优先级确认，避免其他事项挤占她的关键任务时间；需要同级团队，尤其是网络层、服务层负责人，配合确认资源开销和优化目标；需要团队内部形成共识：重点模块不能等完全成熟才汇报，阶段性结论、风险和假设也必须及时公开。

## 提交前自查

- 是否始终围绕同一名成员：是。
- 是否写了真实事实：是，包含评审后一周多未公开输出、私下对接网络层、正在构思代码、希望先输出基础资源分配图等事实。
- 是否至少完成一次真实沟通：是，围绕32节点资源评估进展和延迟汇报进行了沟通。
- 是否写明下一次回看时间：可补充为“下周例会前检查32节点资源评估闭环表和基础资源分配图输出情况”。
